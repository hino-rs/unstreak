# Unstreak

> Duolingo 553日ストリーク・毎日のミッション・毎月のバッジを達成しても、話す/書く力が上達している実感がない——という原体験から出発したプロジェクト。

## コンセプト

- 認識ではなく**自由想起**と**構築速度**を鍛えることに特化する
- 汎用カリキュラムの消化ではなく、**自分固有の弱点**を狙い撃ちする
- 進捗指標はバッジ/ストリークではなく、**予測成功率の推移**という誤魔化しの効かない実力指標を採用する

## 理論的裏付け

- **受容語彙 vs 産出語彙**: 見て分かる語彙と、自分から引き出せる語彙は別物。漢字の「読めるけど書けない」と同じ現象
- **想起の難易度階層**: 認識 < 手がかり想起 < 自由想起。既存アプリの多くは一番簡単な「認識」に留まり続けている
- **アウトプット仮説**: インプットだけでは「わかったつもり」で止まる。産出して詰まって初めて自分の知識の穴に気づく
- **自動化/手続き的知識**: 「知っている」と「瞬時に使える」の間には、時間制限下での意味のある反復産出が必要
- **Leveltの発話生成モデル**: 何を言うかを決める → 文法を組み立てて単語の形を選ぶ → 実際に口を動かして音にする。「話せない」の多くは2つめの「文法を組み立てて単語の形を選ぶ」ことの遅さであり、調音の問題ではない。ここはライティングと共通処理なので、音声を使わずテキストで鍛えても話す力に転移するはず
- **生成効果**: 正解を見るより、間違ってでも一度自分で生成する方が記憶に残る
- **望ましい困難**: 適度な負荷（即答しない、一呼吸置く）が定着を高める
- **ゲーミフィケーションの罠**: ストリーク/バッジが目的化し、本来の目的（実際に使える力）とズレる（Goodhartの法則）。エンゲージメント課金モデルは産出問題より認識問題を優先しがちという構造的インセンティブにも注意

## プロダクト設計

### MVP機能

- **➀画像描写ドリル**：画像を見せて英語で説明させ、AI（採点役=AI1）が正誤判定・添削する

### ロック中（将来実装のプレースホルダーUIのみ用意）

- **➁英語日記**：一日の出来事を英語で記述
- **➂トピック説明**：プロフィール連動（例：IT系なら「スタックを説明して」）で会話的に実践

### AIの役割分担

- **AI1（採点役）**：➀➁➂それぞれの提出物を添削・評価する先生役
- **AI2（辞書相棒）**：「あれ、〇〇って英語でどう言うんだっけ」を気軽に聞ける相棒役。コンテキストは持たない（AI1に見せる文章の内容は見ない）

### 弱点プール（プロダクトの心臓部）

AI1の添削結果とAI2への質問ログを一元集約する個人専用のデータストア。➀➁➂の出題内容や間隔反復に還元し、「自分が実際に詰まった構文・単語」だけを狙い撃ちで再出題する。

### UXの摩擦設計（設計上の核心）

検討の結果、コントロールすべき変数を2軸に分離した：

| 軸 | 方針 | 目的 |
| --- | --- | --- |
| 質問する行為そのものの心理的コスト | 常にほぼゼロに保つ。恥や罰は**質問の瞬間には絶対に乗せない** | 外部の辞書・翻訳ツールへの逃避を防ぐ（質問ログが生命線のため） |
| 答えが返ってくるまでの手続き | 答えを見る前に、**必ず**自分の予想を一度入力させる（スキップ不可） | 「聞けばいいや」精神を防ぎ、生成効果を発生させる |
| 恥・気まずさの演出 | 質問時ではなく、後から振り返り画面で「これ3週間前も聞いたよ」等、遅延して表示 | 質問行為を萎縮させずに、定着しなかったことへの心理的フックだけを作る |

「予想が当たった割合」の推移が、そのままバッジに代わる本物の進捗指標になる。
