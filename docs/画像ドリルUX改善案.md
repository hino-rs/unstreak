# 画像ドリル UX改善案

> 対象:「①画像描写ドリル」(`/practice/describe`)と「絵画ドリル」(`/practice/painting`)。
> 想定ユーザー:高校生レベルの日本人英語学習者。このペルソナで実際に使った場合に離脱しやすいポイントを洗い出し、対応案をまとめる。

## 優先度サマリー

| 優先度 | 項目 | 対象 |
| --- | --- | --- |
| 高 | AI2(辞書相棒)への導線がドリル画面内にない | 共通 |
| 高 | 添削待ち中の進捗表示がない | ①共通 |
| 高 | 絵画ドリルの語彙・題材レベルが高校生と噛み合わない | 絵画 |
| 高 | Round1提出時点で全クレジット前払い、Round2離脱で返金なし | 絵画 |
| 中 | 書き出しのヒントがなく白紙のまま固まる | ① |
| 中 | スキップ(別の画像)のクレジット消費が明示されていない | ① |
| 中 | 気づき判定がキーワード完全一致で語彙が少ない子ほど不利 | 絵画 |
| 中 | 所要時間の見積もりがどこにも出ない | 絵画 |
| 低 | 結果モーダルの情報量が多く優先度がついていない | ① |
| 低 | コンテンツが有限(6枚)で天井がすぐ見える | 絵画 |

> 上記の多くは根本原因が共通している:**ユーザーの学年・英語レベルを持っていないため、全ユーザーに同一の語彙レベル・題材を出している**こと。特に絵画ドリルの問題1・2は、ユーザーレベル設計([後述](#ユーザーレベル設計プロフィール))を入れないと解決しない。

## ①画像描写ドリル(`/practice/describe`)

### 問題1: 何を書けばいいか分からず固まる

- プレースホルダーが `"What is happening in the picture? (e.g. A barista is carefully preparing coffee...)"` のみ(`app/(app)/practice/describe/page.tsx:343`)。高校生には例文中の単語自体が難しく、参考にならない。
- 目安の分量(何語書けば十分か)が示されていない。

**解決案**
- プレースホルダー例文を高校生でも書ける平易な語彙に差し替える、または画像カテゴリごとに簡単な書き出し語("A man is..." "There are...")を1〜2個添える。
- Textarea付近に「3〜4文が目安」など軽い分量ガイドを表示する。

### 問題2: 添削待ち中が完全に無音

- ボタンラベルが「AIが添削中...」に変わるだけで、所要時間の目安や進捗表示がない(`page.tsx:371-381`)。数秒〜十数秒の待ちで「固まった?」と不安になりリロードする懸念。

**解決案**
- ローディング中にスケルトンUIまたは「通常10秒ほどで返ってきます」といった目安テキストを出す。
- 長時間(例: 15秒以上)かかる場合のみ追加メッセージを出す段階的表示にする。

### 問題3: スキップのクレジット消費が不透明

- 「別の画像」ボタン(スキップ)は`CREDIT_COSTS.nextImage`を消費する(`app/(app)/practice/describe/next-image/route.ts:124`)が、UI上に「スキップにもクレジットがかかる」旨の表示が一切ない。何度も押すと知らぬ間に消費が嵩む。

**解決案**
- ボタンのtitle属性または近接テキストに「1クレジット消費」を明記する。
- 直近の残高をヘッダー等に常時表示し、消費の影響を可視化する。

### 問題4: 間違いを見せる心理的ハードルへの配慮がUIにない

- README自体が「質問の瞬間には恥を乗せない」設計思想を掲げているのに、添削提出ボタンは一発勝負で、送信前のクッションがない。

**解決案**
- 送信前に「間違えてもOK、まずは書いてみよう」といった一言を常設で出す。
- 送信ボタンに軽いタメ(例: 一瞬のアニメーション)を入れ、反射的な送信を減らし「望ましい困難」の設計思想と一致させる。

### 問題5: AI2(辞書相棒)への導線が発見しにくい

- `AiAssistantPanel`はグローバル常設(`components/app-shell.tsx:69,80`)だが、ドリル画面内には「分からない単語はここで聞ける」という案内が一切ない。

**解決案**
- Textarea付近に「英語で言い方が分からない単語はAIアシスタントに聞いてみよう」という軽いヒント(初回のみ表示 or 常時小さく表示)を追加する。
- 特定の語で入力が止まった(一定時間キー入力がない等)場合にさりげなく促すマイクロインタラクションも検討可。

### 問題6: 結果モーダルの情報量過多

- 総評・修正全文・エラーカード一覧を`max-w-2xl max-h-[90vh]`のモーダルに全部詰め込んでいる(`page.tsx:57`)。エラーが5〜6件つくとどこから読めばいいか分からなくなる。

**解決案**
- エラーを重大度や頻出度で並び替え、最初は上位2〜3件のみ表示+「もっと見る」で展開。
- 「今日はこの1点だけ覚えて帰ろう」的なフォーカスポイントを総評の下に1行追加する。

### 問題7: 振り返り導線が画面から見えない

- `/review`は存在するが、ドリル完了モーダルから「今日はここが弱点でした」「予測成功率」への接続がない。

**解決案**
- 完了モーダルまたは画面下部に「弱点プールを見る」への軽い導線を追加する。

## 絵画ドリル(`/practice/painting`)

### 問題1: 語彙レベルが「高校生」と噛み合っていない

- AI3のシステムプロンプトが「中〜上級の英語学習者向け」を明言し、`symbolism, allegory, patron, composition, propaganda, idealize`等の語を積極使用する設計(`lib/ai3.ts:70-74`)。高校生には解説文自体が読めない可能性が高い。

**解決案**
- 難易度パラメータ(例: `high_school` / `advanced`)をAI3プロンプトに追加し、ユーザーの学年設定(設定画面に項目を追加)に応じて語彙レベルを切り替える。
- 難語には初出時にだけ簡易な言い換えや日本語の補助語(例: `symbolism (象徴)` )を添える案も検討。

### 問題2: 題材が高校生の前提知識と噛み合わない

- MVP6枚(ナポレオンの戴冠式、デラウェア川を渡るワシントン等)は西洋近代史の知識が前提。設計書自身が「宗教・哲学は内容理解の欠如と英語力の欠如を混同するリスクがある」と保留した理由と同じ問題を、選定した絵画自体が抱えている(`docs/絵画ドリル設計.md:9-12`)。

**解決案**
- Round1に入る前に、ネタバレしない範囲の最小限の場面設定(例: 「これは戦場の一場面です」程度)を1行だけ与える「背景ゼロヒント」オプションを検討する。
- 次バッチで「前提知識が要らない絵画」(風景画・静物画・肖像画等)を混ぜ、前提知識依存を下げる選択肢を用意する。

### 問題3: Round1提出時点で全クレジット前払い、離脱しても返金なし

- `grade*2 + reveal`を一括消費(`app/api/painting/[slug]/round1/route.ts:48,53`)。設計書も「途中離脱は返金しない」と明記(`docs/絵画ドリル設計.md:80`)。Round1提出後に解説が難しすぎて心が折れても、Round2をやらない限りクレジットは戻らない。

**解決案**
- セッション開始前(絵画詳細クリック時 or Round1入力前)に「このセッションは○クレジット消費します。Round1〜Round2まで一気に進みます」という事前確認モーダルを出す。
- 少なくとも「Reveal閲覧後、Round2を書かずに離脱した場合の扱い」をUI上で明示する(現状は暗黙に何も起きないだけ)。

### 問題4: 気づき判定がキーワード完全一致

- `matchNoticeableElements`(`lib/paintings.ts:167-182`)はキーワードのsubstring一致のみで「気づけた/見落とした」を判定。概念的に気づいていても知らない単語(例: `composition`)を使わなければ「見落とした」扱いになり、語彙が少ない子ほど不利になる。

**解決案**
- キーワードリストに平易な同義表現("balanced", "in the middle" 等)を増やす。
- 判定をAI1相当の緩い意味マッチングに置き換える(コスト増と要天秤)か、最低限「厳密一致ではなく緩やかな目安」であることをUI文言で明示し、断定的な「見落とした」という表現を避ける(例: 「〇〇についてはもう少し詳しく書けそうです」)。

### 問題5: 所要時間の見積もりがない

- 一覧画面のカードには絵・タイトル・完了バッジのみで、3ステップ・スキップ不可のセッション時間が想像できない(`painting-catalog-view.tsx`)。

**解決案**
- カードまたは詳細ページ冒頭に「約10〜15分」の目安を表示する。

### 問題6: コンテンツが有限で天井がすぐ見える

- ステージ1は6枚のみ、ステージ2は「近日公開」のプレースホルダー(`painting-catalog-view.tsx:108-142`)。

**解決案**
- MVPの現段階では許容範囲だが、ステージ2投入までの間、完了済み絵画への「別の視点で再挑戦」(例: 別のRound1プロンプトで再度気づきを書く)のような再訪動線を軽く用意すると離脱を防げる。

### 問題7: AI2への導線がここにもない

- 語彙難度が①より高いにもかかわらず、Round1/Round2の入力欄付近に辞書相棒への案内がない。①よりも導線不足の影響が大きい。

**解決案**
- ①と同様のヒント表示を絵画ドリルのTextarea付近にも追加する。

## ユーザーレベル設計(プロフィール)

### 課題

現状プロフィールにレベル概念がなく、AI3の語彙レベルはハードコードで「中〜上級」固定(`lib/ai3.ts:70-74`)。高校生はおろか、対象ユーザーが小学生まで広がりうることを考えると、全員に同じ語彙・題材を出す前提そのものが破綻する。

### 2軸で持たせる

学年と英語力は別物(小学生でも英語が得意な子、高校生でも初心者もいる)なので、プロフィールに2軸で持たせる。

| 軸 | 用途 | 決め方 |
| --- | --- | --- |
| 対象年齢帯(学年) | 出題する題材の選定(例: 絵画ドリルの戦争画のような重い題材を避けるか等) | 自己申告(本人が最も正確に答えられる情報のため、そのまま信頼する) |
| 英語レベル | AI1の添削文・AI3の解説文の語彙レベル切り替え | 自己申告ではなく、後述のキャリブレーション+継続更新で機械的に決める |

英語レベルを自己申告にしない理由:自己申告はブレが大きく(特に子供は過大/過小評価しがち)、かつ「バッジ/ストリークでなく誤魔化しの効かない実力指標」というREADMEの根本思想と矛盾する。かといって従来型の多肢選択式プレースメントテストは「認識」問題であり、README が否定する「認識に留まる既存アプリ」と同じ罠にはまる。そこで、既存の産出ベースの採点エンジン(AI1)をそのまま初期レベル判定に転用する。

### 初期キャリブレーション

1. オンボーディングで学年を自己申告してもらい、対象年齢帯を確定。同時に英語レベルの暫定初期値(例: 小学生→初級、中学生→初級〜中級、高校生→中級)を仮置きし、キャリブレーション時に見せる画像の難易度選定に使う。
2. 画像描写ドリルと同じ仕組みで2〜3問(ジャンルを変えて)書かせ、それぞれAI1に採点させる。1問だけだと「たまたま得意/不得意な話題だった」という揺らぎがそのまま初期レベルとして固定されてしまうため、複数問必須にする。
3. `GradingResultSchema`(`lib/ai1.ts`)に語彙の幅・文の複雑さ・語数あたりの誤り密度をもとにした`level_estimate`(例: beginner / intermediate / advanced、将来的にはCEFR風A1〜B2)を追加出力させる。誤り数だけを見ると「短い文=誤りが少ない=上級」と誤判定しやすいので、語数・構文複雑さも加味する設計にする。
4. 2〜3問の`level_estimate`は平均でなく中央値(または多数決)で集約し、外れ値1問に引っ張られないようにする。

### 継続更新:指数移動平均(EWMA)で揺らぎを吸収

初期キャリブレーションを一度きりの確定値にはしない。ユーザーレベルは「点」ではなく「推移」として扱う(README の「予測成功率の推移」と同じ思想)。

```
level_score = α × 今回のAI1 level_estimate + (1 - α) × 前回のlevel_score
```

- 「直近N件の中央値」のようなスライディングウィンドウ方式は、window境界を1件跨ぐたびに中央値が急にジャンプしうるため揺らぎ対策として弱い。EWMAなら直近を重く見つつ過去の蓄積も緩やかに残るため、1件の外れ値でガクッと変わらない。
- αは小さめ(目安0.15〜0.2)にし、初期の数件で決め打ちせず使うほどじわじわ収束させる。
- コールドスタート(1件目)は前回値がないため、「学年から仮置きした初期値」を`level_score`の初期値として与える。
- 実装は`profiles`テーブルに`level_score`カラムを1つ持たせ、`drill_attempts`/`painting_attempts`の採点完了ごとに更新するだけで済み、window方式のように過去N件をDBから引き直す必要がない。

### ユーザーへの見せ方

初期段階では「だいたい初級〜中級です。使っていくうちに調整されます」のように幅を持たせて提示し、確定的な断定を避ける。これも「一発測定の結果に不安を感じさせない」ための期待値調整として機能する。

### 適用先

- `lib/ai3.ts`のSYSTEM_PROMPTに`level_score`由来の語彙レベル指示を差し込む(絵画ドリルの問題1)。
- `lib/ai1.ts`の添削プロンプトにも同様に語彙レベル指示を渡し、修正例文が難しすぎないようにする。
- 絵画ドリルの題材選定・出題順(将来のステージ2以降)に対象年齢帯を反映する(絵画ドリルの問題2)。

## 次のアクション(提案)

1. まず①③に共通する「AI2導線の明示」「添削待ちの進捗表示」を先に直す(実装コスト低・離脱防止効果大)。
2. ユーザーレベル設計(上記)を優先的に進める。特に絵画ドリルは、学年/レベルに応じてAI3の語彙レベルを切り替えられないと、高校生はおろかそれ以下の年齢層には機能全体が刺さらない。
3. クレジットの事前確認モーダルは、絵画ドリルに限らずプロダクト化タスク(`docs/プロダクト化.md`)の「各クレジット消費画面での残高の事前表示・事前ブロック」と合わせて実装するのが効率的。
